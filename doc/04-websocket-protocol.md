# Этап 4. WebSocket и протокол команд

Полный контракт первой версии: [protocol-v1.md](protocol-v1.md).

## Результат этапа

Телефон отправляет типизированные команды без перезагрузки страницы, сервер
валидирует их и пока только записывает безопасные метаданные в лог.

## Шаги

1. Добавить endpoint `GET /ws`.
2. Зафиксировать версию и JSON-схему протокола.
3. Поддержать команды `move`, `click`, `text`, `key`, `volume` и `mute`.
4. Ввести предел размера сообщения и строгую проверку полей.
5. Добавить ping/pong без idle-отключения и очистку закрытого соединения.
6. Ограничить Agent одной активной Connection.
7. Написать unit- и integration-тесты декодирования, heartbeat и закрытия.
8. Перенести браузерное переподключение с backoff в этап PWA, где появится
   Controller.

Пример:

```json
{"version":1,"type":"move","payload":{"dx":12,"dy":-4}}
```

## Проверка

1. Движение пальца создаёт команды `move`.
2. Один клик создаёт ровно одну команду `click`.
3. Кириллица доходит до сервера без искажения.
4. Повреждённый JSON и неизвестный тип отклоняются без panic.
5. Connection остаётся открытой без команд, пока heartbeat подтверждает связь.
6. После разрыва интеграционный клиент может подключиться снова.

## Критерий готовности

Все типы команд проходят через один валидируемый протокол, ошибки клиента не
роняют процесс, тесты проходят.
