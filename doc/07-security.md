# Этап 7. Минимальная безопасность

## Результат этапа

Управлять ноутбуком может только клиент, получивший одноразовый токен текущего
запуска.

## Шаги

1. Генерировать криптографически случайный токен при запуске.
2. Передавать токен в URL подключения и проверять при WebSocket handshake.
3. Отклонять отсутствующий и неверный токен до выполнения команд.
4. Разрешать только одного активного клиента.
5. Добавить команду локального отключения клиента.
6. Ограничить частоту команд и размер входящих данных.
7. Не писать токены и введённый текст в логи.
8. Документировать использование только в доверенной локальной сети.

## Проверка

1. Соединение без токена получает отказ.
2. Неверный токен не позволяет выполнить ни одной команды.
3. Второй телефон не перехватывает активную сессию.
4. После перезапуска старый токен не работает.
5. Токен и текст отсутствуют в логах.
6. Поток чрезмерно частых команд ограничивается.

## Критерий готовности

Все команды проходят только от одного авторизованного клиента текущей сессии.

## Коммит

`feat: secure local control session`
